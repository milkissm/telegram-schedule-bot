# Технологический стек проекта "Telegram-бот расписания СФУ"

## Язык программирования

### Python 3.10+
Python выбран как основной язык разработки благодаря:
- Низкому порогу входа для команды 
- Богатой экосистеме библиотек для работы с Telegram API, базами данных и парсинга Excel
- Поддержке асинхронного программирования (asyncio), что критично для бота
- Читаемости кода, что упрощает командную работу и code review

## Фреймворк для Telegram-бота

### aiogram 3.x
Выбран вместо устаревшего `telebot` (pyTelegramBotAPI) по следующим причинам:
- Полная асинхронность - бот может обрабатывать множество запросов одновременно без блокировок
- Современная архитектура на основе роутеров  - код легче структурировать и масштабировать
- Встроенная поддержка FSM для пошаговых диалогов 
- Типизация и поддержка Pydantic - меньше ошибок на этапе разработки
- Активная поддержка и соответствие современным стандартам Python

## База данных

### PostgreSQL 15+
Выбрана вместо SQLite по причинам:
- Поддержка сложных связей между таблицами необходима для справочников институтов/групп
- Масштабируемость - если ботом начнут пользоваться сотни студентов, PostgreSQL выдержит нагрузку
- Надёжность и транзакционность - важно при одновременной загрузке расписания и чтении
- Поддержка полнотекстового поиска (может пригодиться для поиска по заметкам)

### SQLAlchemy 2.0 (async)
ORM для взаимодействия Python с PostgreSQL:
- Позволяет работать с базой данных через Python-объекты, а не сырые SQL-запросы
- Поддержка асинхронных запросов (asyncpg) не блокирует работу бота
- Встроенная система миграций через Alembic - удобно обновлять структуру БД
- Защита от SQL-инъекций из коробки

## Работа с Excel-файлами

### pandas + openpyxl
- `pandas` - мощная библиотека для обработки табличных данных, умеет читать Excel с объединёнными ячейками
- `openpyxl` - низкоуровневая библиотека для работы с `.xlsx`, нужна для точного контроля над парсингом сложной структуры файлов
Вместе они позволяют извлекать данные из матричной структуры расписания и преобразовывать их в плоский формат для БД

## Фоновые задачи

### APScheduler 3.x
- Интегрируется с asyncio и aiogram - не блокирует основной цикл бота
- Позволяет запускать задачи по расписанию 
- Поддерживает cron-выражения и интервалы - гибкая настройка времени уведомлений
- Легковесная и не требует отдельного сервера (в отличие от Celery)

## Управление зависимостями и окружением

### python-dotenv
Хранение токена бота, пароля от БД и других секретов в файле `.env`, который не коммитится в Git. Это стандарт безопасности.

### pip + requirements.txt
Стандартный менеджер пакетов Python. Файл `requirements.txt` позволяет любому участнику команды установить все зависимости одной командой: `pip install -r requirements.txt`

### Git + GitHub
Система контроля версий для командной работы. GitHub Projects используется как канбан-доска для управления задачами спринта.

### Zed / PyCharm / VS Code
Редакторы кода с поддержкой Python, Git-интеграцией и линтерами. Выбор зависит от предпочтений участника.
