# Спецификация ZIP-архива и правила валидации Excel-файлов

Документ описывает, какой архив бот принимает от администратора, как устроен
файл расписания СФУ и какие проверки выполняются перед записью данных в базу.

Документ закрывает задачу **1.6**. На него опираются задачи эпика 4: распаковка
архива (4.1), разбор Excel (4.2–4.10) и отчёт администратору (4.11), а также
тесты 9.1 и 9.2.

Все примеры взяты из реальной выгрузки СФУ — расписания ИКИТ за осенний
семестр 2026/27. Это важно: спецификация описывает не удобный формат, а тот,
который действительно приходит.

## 1. Границы

Что делает бот: принимает архив, проверяет его, разбирает файлы, записывает
расписание в базу и сообщает отчёт.

Чего бот не делает:

- не скачивает расписание с сайта СФУ — архив готовит человек (роли, п. 1.4);
- не редактирует расписание вручную;
- не сравнивает старое и новое расписание — по US-13 студент получает одно
  уведомление без перечня изменений.

## 2. Требования к архиву

| Параметр | Требование |
|---|---|
| Формат | ZIP (`.zip`) |
| Содержимое | файлы расписания `.xls` и `.xlsx` в корне архива |
| Смешивание форматов | допускается: `.xls` читается `xlrd`, `.xlsx` — `openpyxl` (см. К4) |
| Имена файлов | любые: институт, курс и семестр определяются по содержимому, а не по имени |
| Вложенные папки | не поддерживаются: файлы из подпапок пропускаются с предупреждением |
| Вложенные архивы | запрещены |
| Файлы других типов | запрещены, кроме служебных `__MACOSX` и `.DS_Store` — они игнорируются |
| Защита паролем | не поддерживается: файл считается нечитаемым |
| Размер архива, число файлов, объём после распаковки | задаются константами, значения появятся в эпике 4 (раздел 8) |

Имя файла намеренно не используется. В реальной выгрузке имя
`IKIT_3_kurs_OSEN26-27.xls` — удобное совпадение, а не правило: СФУ может
назвать файл `расписание(1).xls`. Институт, курс и семестр берутся из шапки
листа, поэтому переименование файла ничего не ломает.

## 3. Структура Excel-файла

Один файл — одно расписание для одной пары «институт + курс + форма обучения».

### 3.1. Шапка

| Строка | Содержимое | Пример |
|---|---|---|
| 1 | заголовок | `РАСПИСАНИЕ УЧЕБНЫХ ЗАНЯТИЙ` |
| 2 | семестр и учебный год | `Осенний семестр`, `2026-2027` |
| 3 | институт | `Институт:` → `ИКИТ` |
| 4 | курс и форма обучения | `Курс:` → `3.0`, `Форма обучения` → `Очная` |
| 6 | заголовок таблицы: `Дни`, `Часы`, `Неделя`, далее коды направлений | `27.03.03 Системный анализ и управление` |
| 7 | названия групп с подгруппами | `КИ24-03Б (1 подгруппа)` |

Строка 0 может содержать техническую запись `Группа: КИ24-17/1Б` — остаток от
выгрузки. Парсер её игнорирует.

Коды направлений в строке 6 (`09.03.01`, `27.03.03` и т.д.) обозначают начало
группы колонок, но для разбора не нужны: нас интересуют только имена групп из
строки 7.

### 3.2. Таблица занятий

| Колонка | Содержимое | Когда заполнена |
|---|---|---|
| A | день недели (`Понедельник` … `Суббота`) | только в первой строке дня |
| B | время пары (`8.30 - 10.05`) | только в первой строке слота |
| C | номер недели (`1` или `2`) | только в строке начала занятия |
| D и далее | по одной колонке на группу и подгруппу | построчно |

Строка 7 для ИКИТ содержит 52 колонки групп: `КИ24-06Б (1 подгруппа)`,
`КИ24-06Б (2 подгруппа)`, `КИ24-07Б (1 подгруппа)` и так далее до
`КИ24-21Б (2 подгруппа)`.

### 3.3. Слот и занятие

**Слот** — строки от одного заполненного значения в колонке «Часы» до
следующего. В реальном файле слот занимает 12 строк и содержит два занятия:
шесть строк для недели 1 и шесть для недели 2.

**Занятие** внутри колонки группы — шесть подряд идущих строк:

| Порядок | Содержимое | Пример |
|---|---|---|
| 1 | предмет | `Теория управления` |
| 2 | преподаватель | `Кривова Д.Д.` |
| 3 | тип занятия | `пр. занятие` |
| 4 | корпус | `Корпус №17` |
| 5 | аудитория | `4-02` |
| 6 | формат проведения | `синхронно` |

Реальный фрагмент (понедельник, первая пара, колонка группы `КИ24-07Б`,
подгруппа 1; колонки A, B, C и одна колонка группы):

```text
A            B              C   значение в колонке группы
Понедельник  8.30 - 10.05   1   Теория управления
                                Кривова Д.Д.
                                пр. занятие
                                Корпус №17
                                4-02
                                синхронно
                            2   Теория управления
                                Кривова Д.Д.
                                пр. занятие
                                Корпус №17
                                4-02
                                синхронно
```

Здесь видно устройство слота: время указано один раз, затем идут два
шестистрочных блока — для недели 1 и для недели 2. Предмет в обеих неделях
совпадает, но это не гарантировано: часто первая неделя и вторая заполнены
разными занятиями.

### 3.4. Допустимые значения

| Поле | Значения |
|---|---|
| День недели | `Понедельник`, `Вторник`, `Среда`, `Четверг`, `Пятница`, `Суббота` |
| Неделя | `1`, `2` |
| Время пары | `8.30 - 10.05`, `10.15 - 11.50`, `12.00 - 13.35`, `14.10 - 15.45`, `15.55 - 17.30`, `17.40 - 19.15` |
| Тип занятия | `лекция`, `пр. занятие`, `лаб. работа`, `практика` |
| Формат проведения | `синхронно`, `асинхронно` |
| Форма обучения | `Очная`, `Заочная`, `Очно-заочная` |
| Семестр | `Осенний семестр`, `Весенний семестр` |

Номер пары не хранится в файле, он вычисляется из времени по таблице выше:
`8.30 - 10.05` — пара 1, `17.40 - 19.15` — пара 6.

Время записано с точками (`8.30`), а не с двоеточиями. Это особенность выгрузки
СФУ, а не ошибка файла: сравнение должно быть нормализованным, чтобы `8.30` и
`08:30` считались одним значением.

### 3.5. Служебные листы

| Лист | Назначение | Нужен парсеру |
|---|---|---|
| `Расписание` | сами занятия | да |
| `Институты` | справочник для выпадающих списков Excel: коды институтов, годы, семестры, формы обучения, типы занятий | нет |
| `Группы` | список групп института | нет |
| `Дисциплины` | список дисциплин | нет |
| `Преподаватели` | список преподавателей | нет |
| `Аудитории` | список корпусов и аудиторий | нет |

Служебные листы заполняет сам Excel, чтобы человек выбирал значения из списка.
Парсер их не читает: если данные в листе `Расписание` и в листе `Группы`
разойдутся, источником истины считается `Расписание`.

Лист `Институты` содержит служебные записи: `АСПИРАНТУРА`, `ПОНОП`, `СФУ` и
13 институтов с пометкой `(ликвидирован)`. Загружать этот список в справочник
нельзя — в базе должны остаться только действующие институты.

### 3.6. Исключения в реальных данных

Файл СФУ не идеален, и это заложено в правила. В конкретной выгрузке ИКИТ
встречаются:

| Случай | Как выглядит | Что делает парсер |
|---|---|---|
| неделя не указана | в слоте нет ни одной отметки в колонке «Неделя», а занятие продублировано дважды | занятие применяется к обеим неделям, предупреждение W04 |
| лишняя строка в блоке | в конце занятия вторая строка `синхронно` | игнорируется, предупреждение W05 |
| пустые ячейки в конце слота | строки заполнены только в части колонок | пустые колонки пропускаются |
| подвал | `Примечание: …`, `Руководитель учебного департамента …`, `Врио директора института …` | разбор прекращается, предупреждение W06 |
| подгруппы с одинаковыми данными | лекция записана и в колонке 1-й, и в колонке 2-й подгруппы | создаются две записи расписания, по одной на подгруппу |

Последний случай важен: лекция для всей группы дублируется в колонках обеих
подгрупп. Это не ошибка файла, а способ показать, что занятие общее.

## 4. Алгоритм разбора

1. Открыть книгу, найти лист `Расписание`. Нет листа — ошибка E06.
2. Прочитать шапку: институт, курс, форма обучения, семестр, учебный год.
   Нет обязательного поля — ошибка E07.
3. Найти строку с именами групп: первая строка после заголовка, где в колонке D
   и далее есть значения. Нет такой строки — ошибка E09.
4. Пройти по строкам снизу от шапки. Заполненная колонка A задаёт день,
   заполненная колонка B открывает слот и задаёт время.
5. Внутри слота найти подблоки по маркеру недели. Маркеров нет — весь слот
   считается одним занятием для обеих недель.
6. Для каждой колонки группы собрать непустые значения подблока сверху вниз.
7. Разобрать значения по шаблону: предмет, преподаватель, тип занятия, корпус,
   аудитория, формат. Не совпало с шаблоном — ошибка E10 с номером строки.
8. Проверить значения по справочникам раздела 3.4. Нарушение — ошибка E13–E14.
9. Проверить дубли: одна группа, день, пара и неделя не могут встречаться
   дважды. Совпадение — ошибка E15.
10. Записать занятия в базу.

Шаблон разбирается не по жёстким номерам строк, а по признакам: тип занятия —
значение из списка `лекция` / `пр. занятие` / `лаб. работа` / `практика`,
корпус начинается с `Корпус`, формат — `синхронно` или `асинхронно`. Всё, что
стоит до типа занятия и не является предметом, считается преподавателем: в
файлах встречаются двойные фамилии в одной строке.

## 5. Правила валидации

Проверки делятся на две категории:

- **Ошибка (E)** — файл не применяется целиком, данные из него в базу не
  попадают. Остальные файлы архива при этом обрабатываются (US-12, сценарий 2).
- **Предупреждение (W)** — файл применяется, случай попадает в отчёт.

### 5.1. Уровень архива

| Код | Проверка | Категория |
|---|---|---|
| E01 | файл не является ZIP-архивом | ошибка |
| E02 | в архиве нет ни одного файла `.xls` / `.xlsx` | ошибка |
| E03 | размер архива превышает лимит | ошибка |
| E04 | в архиве есть вложенный архив | ошибка |
| W01 | в архиве есть файлы других типов | предупреждение, файл пропускается |
| W02 | файл лежит в подпапке | предупреждение, файл пропускается |

При E01–E03 загрузка прекращается полностью: расписание в базе не меняется.

### 5.2. Уровень файла

| Код | Проверка | Категория |
|---|---|---|
| E05 | файл не открывается: повреждён или защищён паролем | ошибка |
| E06 | нет листа `Расписание` | ошибка |
| E07 | в шапке нет института, курса, формы обучения или семестра | ошибка |
| E08 | институт из шапки отсутствует в справочнике | ошибка |
| E09 | не найдена строка с именами групп | ошибка |
| W03 | курс в шапке не совпадает с курсом, вычисленным по имени группы | предупреждение |

E08 — ошибка, а не автоматическое создание института: вуз не может появиться
сам по себе, это признак чужого файла. Группы, наоборот, создаются
автоматически (см. `docs/database_schema.md`, раздел 6).

### 5.3. Уровень данных

| Код | Проверка | Категория |
|---|---|---|
| E10 | блок занятия не разбирается по шаблону | ошибка |
| E11 | время пары не совпадает ни с одной парой из раздела 3.4 | ошибка |
| E12 | номер недели не `1` и не `2` | ошибка |
| E13 | день недели не из списка | ошибка |
| E14 | пустой предмет | ошибка |
| E15 | дубль: группа, день, пара и неделя встречаются дважды | ошибка |
| W04 | неделя не указана, занятие применено к обеим неделям | предупреждение |
| W05 | в блоке лишние строки, они проигнорированы | предупреждение |
| W06 | достигнут подвал файла, разбор прекращён | предупреждение |
| W07 | неизвестный формат проведения (`синхронно`, `асинхронно`, пусто) | предупреждение, формат не сохраняется |

Ошибки уровня данных относятся к файлу целиком, а не к одной строке: файл
смешанного качества применить частично нельзя — получится расписание, в
котором у группы пропала часть пар, и студент об этом не узнает.

### 5.4. Смысловые проверки

| Проверка | Что делает |
|---|---|
| группа уже есть в базе | используется существующая запись |
| группы нет в базе | создаётся институт → курс → группа → подгруппа |
| в файле есть только часть групп института | расписание остальных групп не меняется |
| расписание группы уже было загружено | старые занятия группы удаляются, записываются новые (US-12, сценарий 3) |

## 6. Отчёт администратору

После разбора бот отправляет одно сообщение:

```text
Загрузка завершена.

Файлов в архиве: 3
Разобрано: 2
Ошибок: 1

Загружено пар: 412
Обновлено групп: 27
Новых групп: 2

Ошибки:
• raspisanie_2.xls — E08: институт «ИЭУП» отсутствует в справочнике
• raspisanie_3.xlsx — E14: пустой предмет, строка 87

Предупреждения:
• raspisanie_1.xls — W04: неделя не указана, занятие применено к обеим неделям (4 случая)
```

Правила отчёта:

- ошибки перечисляются с кодом, файлом и, где возможно, номером строки;
- одинаковые предупреждения группируются с указанием количества;
- если ошибок нет, раздел «Ошибки» не выводится;
- отчёт отправляется даже при полном провале загрузки.

Код ошибки в отчёте нужен тестам: задача 9.2 проверяет, что на невалидном
архиве бот выдал именно ожидаемый код, а не «что-то пошло не так».

## 7. Поведение при частичных ошибках

| Ситуация | Поведение |
|---|---|
| архив не открывается (E01–E03) | расписание не меняется, администратор получает отчёт |
| часть файлов с ошибками | корректные файлы применяются, проблемные перечисляются |
| все файлы с ошибками | расписание не меняется, администратор получает отчёт |
| файл применён | студенты групп из этого файла получают уведомление (US-13) |
| группа была в файле, но занятия не распознаны | данные группы не меняются |

Последний пункт — сознательное решение: лучше оставить устаревшее расписание,
чем стереть его и оставить студента без данных.

## 8. Параметры, которые нужно завести в константы

Константы — единый источник значений, поэтому числа в этом документе не
фиксируются. В эпике 4 добавляются:

| Параметр | Назначение | Предлагаемое значение |
|---|---|---|
| `MAX_ARCHIVE_SIZE_MB` | предел размера архива | 20 |
| `MAX_ARCHIVE_FILES` | предел числа файлов в архиве | 50 |
| `MAX_UNPACKED_SIZE_MB` | защита от zip-бомбы | 200 |
| `ALLOWED_EXTENSIONS` | `.xls`, `.xlsx` | — |
| `PAIR_TIMES` | соответствие номера пары и времени | 6 пар из раздела 3.4 |
| `LESSON_TYPES` | допустимые типы занятий | 4 значения из раздела 3.4 |
| `DAYS_OF_WEEK` | дни недели | уже есть в К3 |

`PAIR_TIMES` нужен потому, что в базе хранится номер пары, а бот показывает
время начала и конца. Без этой таблицы расписание выводилось бы как «пара 3»
вместо «12.00–13.35».

## 9. Что не поддерживается

| Случай | Почему |
|---|---|
| несколько институтов или курсов в одном файле | в выгрузке СФУ один файл — одна пара «институт + курс»; иначе шапка неоднозначна |
| `.xlsm` с макросами | макросы не нужны, риск безопасности |
| файл, защищённый паролем | нет способа получить пароль от администратора |
| расписание в PDF или картинкой | задача формата не предусматривает, распознавание изображений вне объёма |
| Google Sheets и ссылки | бот принимает файл, а не ссылку (роли, п. 1.4) |
| заочная форма со своим форматом | формат файлов заочного отделения не проверялся; при появлении — отдельная задача |
| синхронность занятия в базе | в модели не хранится: интерфейс бота её не показывает |
